# Запуск нового проекта на HerPlex

Инструкция по запуску реального проекта по multi-agent воркфлоу.

---

## Шаг 1 — Владелец: подготовка

1. Создать новый GitHub-репозиторий для проекта
2. Скопировать в новый репо следующие файлы из HerPlex:
   - `AGENTS.md` — правила Hermes
   - `PERPLEXITY.md` — правила Perplexity
   - `HerPlex.md` — очистить разделы истории, оставить только заголовок, модель и протокол
   - `templates/task.md` и `templates/review.md`
   - `docs/pipeline.md`, `docs/agent-contract.md`, `docs/quality-gates.md`
3. Описать Perplexity проект:
   - что нужно сделать
   - стеки и ограничения
   - что нельзя трогать

---

## Шаг 2 — Perplexity: архитектура и первое задание

1. Читает описание проекта от владельца
2. Пишет `docs/architecture.md` — структура, модули, решения
3. Формулирует первое задание H-001 для Hermes в `HerPlex.md`
4. Если есть архитектурная неопределённость — задаёт один вопрос владельцу до запуска

---

## Шаг 3 — Hermes: реализация

1. Читает `HerPlex.md`, находит H-001
2. Выполняет задание, коммитит, отчитывается в `HerPlex.md`
3. Дальше — только по явному заданию Perplexity или владельца. Автономный backlog-режим отключён по умолчанию; включается только по явному решению владельца.

---

## Шаг 4 — Рабочий цикл

```
Hermes выполнил → отчёт в HerPlex.md
→ Perplexity читает → review или следующее задание
→ Hermes выполняет
→ повторить
```

---

## Когда подключается владелец

- Perplexity задал архитектурный вопрос
- Hermes сработал триггер spiral
- Требуется human approval (секреты, деплой, миграции)
- Perplexity запросил review

---

## Что не нужно копировать из HerPlex

- Историю заданий H-001..H-005 из `HerPlex.md`
- `examples/feature-cycle/` — это методология, не шаблон проекта
- `CONTEXT.md` — специфичен для HerPlex, не переносить
- `TODO.md` — заполняется заново для каждого проекта
